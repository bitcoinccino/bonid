Verify a BonID in three steps

BonID lets your app confirm who someone is: a bank opening an account, a clinic checking in a patient, an embassy checking a document. Start in the sandbox, then switch to production when you're ready.

  1. Become a partner

    Apply on the partners page. Once BonID approves your organization, your API credentials are created for you.

  2. Get your API key

    Sign in to the partner portal and open API keys. Your OAuth client ID and secret arrive in a one-time secure link (valid 72 hours, viewable once), so save them right away.

  3. Make your first call

    Check whether a BonID is valid. Replace YOUR_API_KEY and run:

curl /identity/BZ-1970-M-ND-P2334-0B6/status \
  -H "X-Partner-Api-Key: YOUR_API_KEY"
// Response
{
  "status": "success",
  "bonid": "BZ-1970-M-ND-P2334-0B6",
  "verification": { "found": true, "verified": true, "status": "approved" }
}

Verify an identity

The quickest check: does this BonID exist, is it approved, and is it still valid? You get a yes/no answer without any personal details.

API key Usually under 200ms 
curl /identity/BZ-1970-M-ND-P2334-0B6/status \
  -H "X-Partner-Api-Key: YOUR_API_KEY"

Need the person's name, photo or address? Those are only shared after the citizen approves. Use Ask for consent, then call the full identity endpoint with the consent_token. Without it, you only get the verification status.

Endpoints

  • GET/identity/{bonid}/statusYes/no status check
  • GET/identity/{bonid}Full details (with consent)

Ask a citizen for consent

For a transaction, like a wire transfer or opening an account, the citizen approves your request in BonID with a code and a face check. You only receive the details they agreed to share.

You can only send requests to citizens whose identity is verified right now. If their identity has expired or been suspended, you get 403 with "reason": "bonid_not_verified", and they can't approve requests already sent.

API key 40+ transaction types
  1. Send the request

    Say what the transaction is and which details you need. Add a callback_url to be notified of the answer.

curl -X POST /transaction_consents \
  -H "X-Partner-Api-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "bonid": "BZ-1970-M-ND-P2334-0B6",
    "transaction_type": "wire_transfer",
    "scopes": ["profile", "address"],
    "amount": 5000,
    "currency": "HTG",
    "callback_url": "https://your-app.com/bonid/webhook"
  }'
  1. The citizen approves (or declines) in BonID

    If they don't answer, the request expires, after 5 to 15 minutes depending on the transaction type.

  2. Get the answer

    BonID sends a signed request to your callback_url (see Webhooks). You can also check the status yourself any time with the consent_token.

  3. Fetch the approved details

    You get only what the citizen approved. The token works for 10 minutes after approval. For money transfers and payments it works only once, so fetch everything you need in a single call.

curl "/identity/BZ-1970-M-ND-P2334-0B6?consent_token=CONSENT_TOKEN" \
  -H "X-Partner-Api-Key: YOUR_API_KEY"

Signing citizens in with BonID (OAuth / OpenID Connect)

If you want a "Sign in with BonID" button rather than per-transaction approval, use the OAuth flow: request consent, exchange the code for a token, then read the profile from /userinfo.

  • POST/request_consentStart sign-in
  • POST/oauth/tokenExchange code for token
  • GET/userinfoRead the profile
  • GET/.well-known/openid-configurationOpenID discovery

Scan a QR code

Every BonID carries a signed QR code. Scan it with your app, send what you read to BonID, and get back whether it's genuine along with the citizen's name and photo.

API key Uses credits 
curl -X POST /qr_scan \
  -H "X-Partner-Api-Key: YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "qr_data": "CONTENTS_OF_THE_QR_CODE" }'

Endpoints

Webhooks

BonID tells your server when something changes, so you don't have to keep asking. Every notification is a signed POST. Check the signature before trusting it.

Sent toWhenEvents
The callback_url on a consent requestThe citizen approves, declines or lets it expiretransaction_consent.approved, .denied, .expired
The webhook URL on your partner accountA citizen's consent or BonID changesconsent.approved, consent.revoked, consent.restored, bonid.changed, bonid.suspended

Headers on every notification

HeaderWhat it is
X-BonID-EventWhat happened, e.g. transaction_consent.approved
X-BonID-SignatureHMAC-SHA256 of the raw request body, using your webhook secret (hex)
X-BonID-TimestampWhen it was sent (Unix seconds)

When you receive consent.revoked, you must delete or anonymize that citizen's data within 30 days. The payload includes the deadline.

Check the signature

const crypto = require("crypto");

// rawBody must be the exact bytes BonID sent (not re-serialized JSON)
function isFromBonID(rawBody, signature) {
  const expected = crypto
    .createHmac("sha256", process.env.BONID_WEBHOOK_SECRET)
    .update(rawBody)
    .digest("hex");
  return signature?.length === expected.length &&
    crypto.timingSafeEqual(Buffer.from(signature), Buffer.from(expected));
}
expected = OpenSSL::HMAC.hexdigest(
  "SHA256", ENV.fetch("BONID_WEBHOOK_SECRET"), request.raw_post
)
signature = request.headers["X-BonID-Signature"].to_s

head :unauthorized unless ActiveSupport::SecurityUtils.secure_compare(expected, signature)
import hashlib, hmac, os

def is_from_bonid(raw_body: bytes, signature: str) -> bool:
    expected = hmac.new(
        os.environ["BONID_WEBHOOK_SECRET"].encode(), raw_body, hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(expected, signature or "")

Reply with any 2xx status quickly. If your server fails, BonID tries again a few times with growing delays. Don't have your webhook secret? Email support@bonid.ht.

Background checks

Authorized partners, such as the police and embassies, can check whether a person has a criminal record or active warrants, and pull incident reports.

API key + access token Approval required 
curl /crime_status/BZ-1970-M-ND-P2334-0B6 \
  -H "X-Partner-Api-Key: YOUR_API_KEY" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"

These endpoints need both your API key and an access token with the right permission (crime:status, crime:reports or crime:certificate). How much detail you see depends on your access level. Crime status checks are limited to 50 requests per 15 minutes.

Endpoints

  • GET/crime_status/{bonid}Record & warrant check
  • GET/incident_reportsSearch incident reports
  • GET/incident_reports/{id}/certificateSigned report certificate
  • GET/officers/{badge_id}/complaints/summaryOfficer complaint summary

Check a certificate

Someone handed you a BonID certificate, such as a police report? Confirm its signature is genuine. No account needed.

Public, no key 
curl -X POST /certificates/verify \
  -H "Content-Type: application/json" \
  -d '{
    "certificate_id": "A3F8B2C1",
    "report_id": "PNH-DDO-20260512-NB17",
    "algorithm": "RSASSA-PSS",
    "issued_at": "2026-05-12T10:30:00Z",
    "signature_value": "BASE64_SIGNATURE"
  }'

Working offline? Download the public key once and check signatures yourself.

Endpoints

  • POST/certificates/verifyCheck a signature
  • GET/certificates/public_keyPublic key for offline checks
  • GET/public/bonid_lookupPublic BonID lookup

Elections (BonVote)

Anyone can confirm that a ballot receipt was counted, with no login. Voter eligibility checks run from the official BonID app after a face check.

Receipt check is public 
curl /election/2026-presidential-round1/verify/RECEIPT_HASH

# { "verified": true, "message": "Vòt ou konte", ... }

Eligibility checks and casting a ballot only work from the official BonID app, which proves it's genuine with signed headers. They aren't part of a partner integration.

Endpoints

  • GET/election/{election_id}/verify/{hash}Check a receipt (public)
  • GET/election/{election_id}/eligibilityVoter eligibility (BonID app)
  • POST/election/{election_id}/kiosk/registerSet up a consulate kiosk
  • POST/election/{election_id}/kiosk/scanScan a voter at a kiosk

Authentication

Most requests only need your API key. Sensitive data, like background checks, also needs an access token.

WhatHeaderWhen you need it
API keyX-Partner-Api-Key: YOUR_API_KEYEvery partner request
Access tokenAuthorization: Bearer YOUR_ACCESS_TOKENBackground checks and incident reports (together with the API key), and OAuth sign-in
NothingnonePublic checks: certificates, ballot receipts, public keys

Permissions (scopes)

Access tokens carry permissions. If one is missing, you get a 403 that names the permission you need.

ScopeLets you
identity:verifyCheck identity status and details
crime:statusRun background checks
crime:reportsSearch incident reports
crime:certificateDownload signed report certificates
officer:complaintsRead officer complaint summaries

Keep your API key and secrets on your server. Never put them in a mobile app or website code that users can download.

Errors & limits

Errors come back as JSON with an error message you can log or show.

StatusMeaningWhat to do
401Missing or wrong API key or tokenCheck the headers and that the key is for this environment
403Not allowed: your token lacks a permission, your sector can't use that type or detail, or the citizen's BonID isn't currently verifiedRead error; the response lists what you're allowed (required_scope, allowed_types or allowed_scopes) or gives reason: bonid_not_verified
404BonID or record not foundCheck the ID for typos
422Something in the request is missing or invalidRead the error message
429Too many requestsWait for the Retry-After seconds, then retry
